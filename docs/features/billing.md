# Billing — Frontend Feature Specification

**Status:** Planned / Phase 2

## Purpose

Display monthly billing records generated by the backend recurring-billing engine.

The backend roadmap defines a state machine along the lines of:

```text
pending
  ↓
generated
  ↓
partially_paid
  ↓
paid
  ↓
overdue
  ↓
written_off
```

The exact final states must come from the backend contract.

## Views

### Lease billing summary

Show:

- current period
- amount due
- amount paid
- balance
- due date
- status

### Billing history

Table:

- period
- generated date
- due date
- billed amount
- paid amount
- balance
- status

## Payment entry

Payment recording should originate from a billing record whenever the backend supports that relationship.

## Overdue state

Overdue must be visually prominent but not treated as a client-calculated truth. The backend determines whether grace period/late fees have made a record overdue.

## Acceptance criteria

- Billing records are displayed exactly as returned by the API.
- Partial payments show paid and outstanding amounts.
- Overdue state is backend-authoritative.
- User can initiate payment recording from an eligible billing record.
- Duplicate generation/retry is invisible to the UI once the backend is idempotent.
